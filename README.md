# fakeflix

A self-hosted media stack on Proxmox: Terraform creates the container, Ansible installs and updates the services.

Everything is served under one domain (`proxy_domain`, default `fakeflix.meme.ar`):

| URL | Service | What it does |
|---|---|---|
| `/` | Homepage | Dashboard linking to everything, with live stats |
| `/radarr` | Radarr | Movies |
| `/sonarr` | Sonarr | Series |
| `/bazarr` | Bazarr | Subtitles |
| `/prowlarr` | Prowlarr | Indexer manager |
| `/qbittorrent` | qBittorrent | Torrent client |
| `requests.` subdomain | Seerr | Request UI. It can't run in a folder, see below |
| (internal) | FlareSolverr | Cloudflare bypass for Prowlarr |
| (internal) | Configarr | Syncs TRaSH-guide quality profiles into Radarr and Sonarr |

Traefik is the reverse proxy in front of all of it. It runs as one more container in the same LXC, and it can also front services on your other VMs and LXCs (see [Services on other machines](#services-on-other-machines)). Each app's own port (`:7878`, `:8989`, …) also still works directly.

## Design

- **One unprivileged Debian 12 LXC on Proxmox**, with nesting turned on, running Docker. It is lighter than a VM, and the host's `/mnt/disk` is bind-mounted in directly, so you don't need NFS or SMB.
- **Docker Compose, generated by Ansible.** Each service is one entry in a YAML catalog (`ansible/group_vars/all/services.yml`). Ansible renders a single `compose.yml` from it, so every container shares one network and can reach the others by name (`qbittorrent:8080`, `flaresolverr:8191`, …).
- **Fully wired up, no clicking.** After the containers start, the `configure` role connects everything through each app's API (details below). [Configarr](https://github.com/raydak-labs/configarr) loads the TRaSH-guide quality profiles. Re-running it is safe: it only changes what's out of place.
- **Traefik + Homepage, generated from the catalog.** A service's `web:` block decides its folder (or subdomain) and its homepage tile. Ansible writes Traefik's routes and the homepage tiles from that, and tells each app its base path.
- **Updating means running a playbook again.** `update.yml` pulls newer images, recreates only the containers whose image changed, and re-applies the wiring and the TRaSH profiles.
- **The Ansible part works without Terraform.** Point the inventory at any Debian or Ubuntu VM, LXC or bare-metal box.

```
terraform/            Proxmox LXC + generates ansible/inventory/hosts.yml
ansible/
  site.yml            full install (idempotent, re-run any time)
  update.yml          update containers (optionally the OS too)
  group_vars/all/
    main.yml          paths, PUID/PGID, timezone
    services.yml      the service catalog  <-- add services here
  roles/
    common/           base packages, timezone, media dirs
    docker/           Docker Engine + compose plugin from docker.com
    stack/            renders compose.yml and runs it
    configure/        wires the apps together via their APIs + runs Configarr
  group_vars/all/
    integrations.yml  API keys, logins, indexers, TRaSH templates, subtitles
    proxy.yml         domain, HTTPS, homepage
  templates/          config files rendered for services (Traefik, Homepage)
  secrets/<host>/     generated API keys (git-ignored, keep a backup)
```

## Networking

The container has **one static IP**, which you set in `terraform/terraform.tfvars`:

```hcl
ipv4_address = "192.168.1.50/24"   # CIDR
ipv4_gateway = "192.168.1.1"
bridge       = "vmbr0"             # optional: vlan_id = 20
```

Terraform also writes that IP into `ansible/inventory/hosts.yml`, which is how Ansible finds the box. Inside the container, Docker runs the apps on a private bridge network. Each app's port is published on the container's IP, so you reach them at `http://192.168.1.50:7878` and so on. Between themselves, the apps use their container names (`http://radarr:7878`). Ports are set per service in `services.yml`.

## Domain, reverse proxy and HTTPS

Settings live in `ansible/group_vars/all/proxy.yml`:

```yaml
proxy_domain: fakeflix.meme.ar
proxy_https: false
```

1. **DNS:** point `fakeflix.meme.ar` and a wildcard `*.fakeflix.meme.ar` at the container's IP. The wildcard covers `requests.` (Seerr) and any subdomain you add later. Without a wildcard, add each subdomain yourself. LAN-only? Use a local DNS entry (router, Pi-hole, AdGuard) or `/etc/hosts`.
2. **HTTPS (optional):** set `proxy_https: true` and `proxy_acme_email`, then pick how Let's Encrypt verifies the domain:
   - `proxy_acme_challenge: http`: port 80 of the domain must be reachable from the internet.
   - `proxy_acme_challenge: dns`: works for a LAN-only box. Set `proxy_acme_dns_provider` (e.g. `cloudflare`) and its API token in `proxy_acme_env` (e.g. `CF_DNS_API_TOKEN`). The variable names for each provider are listed [here](https://doc.traefik.io/traefik/https/acme/#providers).

**Why Seerr is on a subdomain:** Seerr has no setting for running under a path, and its UI breaks behind a folder prefix. To use a different name, change `web.subdomain` for Seerr, e.g. via `stack_service_overrides: {seerr: {web: {subdomain: pedir}}}`.

> ⚠️ **Don't expose this to the internet as-is.** Radarr, Sonarr, Prowlarr and Bazarr have no login, so anyone who can reach the domain can control them. Keep it on your LAN or VPN. If you do open it up, set `proxy_basic_auth_users` in `proxy.yml`, which puts one password in front of everything.

**Homepage** shows one tile per service, with live numbers (queue, wanted, download speed…) pulled using the API keys Ansible manages. Services on other machines get tiles too, see below. The Seerr tile shows an error until you've done its first-time setup.

## Storage layout

Everything is configured in `ansible/group_vars/all/main.yml`:

```yaml
media_dirs:                 # where the folders are on the Docker host (created if missing)
  downloads: /mnt/disk/Downloads
  movies: /mnt/disk/movies
  series: /mnt/disk/series
  music: /mnt/disk/music

media_mounts:               # how they're mounted into the apps (host: container)
  /mnt/disk: /data
```

With the defaults, the apps see the folders at `/data/Downloads`, `/data/movies`, `/data/series` and `/data/music`. Because one mount covers all the folders, imports from Downloads into the library are instant hardlinks or moves instead of copies. The deploy prints the in-app path of each folder. It fails early if a folder isn't under any mount.

You can rename folders, add more (`anime: /mnt/disk/anime`) or put them on other disks. For example, movies on a second disk:

```hcl
# terraform.tfvars: bind-mount both disks into the LXC
media_mounts = {
  "/mnt/disk"  = "/mnt/disk"
  "/mnt/disk2" = "/mnt/disk2"
}
```
```yaml
# group_vars/all/main.yml
media_dirs:
  downloads: /mnt/disk/Downloads
  movies: /mnt/disk2/movies
  series: /mnt/disk/series
  music: /mnt/disk/music
media_mounts:
  /mnt/disk: /data
  /mnt/disk2/movies: /data/movies
```

Hardlinks only work within a single disk. Movies on a different disk from Downloads will be copied on import.

App configs and databases are stored in `/opt/fakeflix/appdata/<service>` inside the LXC.

## Usage

### Requirements (on your workstation)

- Terraform ≥ 1.5 (or OpenTofu)
- Ansible ≥ 2.15
- An SSH key (`~/.ssh/id_ed25519.pub` by default)

### 1. Create the container

```sh
cp terraform/terraform.tfvars.example terraform/terraform.tfvars
$EDITOR terraform/terraform.tfvars
make infra
```

> Proxmox only lets **`root@pam` with a password** create bind mounts. An API token won't work for that part. If you'd rather use a token, set `media_mounts = {}` and add the mount points by hand.

**Permissions (unprivileged LXC):** container UID 1000 maps to host UID 101000. Run this once on the Proxmox host:

```sh
chown -R 101000:101000 /mnt/disk/Downloads /mnt/disk/movies /mnt/disk/series /mnt/disk/music   # your media_dirs
```

If you'd rather not change ownership, set `unprivileged = false` in `terraform.tfvars`. Changing this recreates the container.

### 2. Install everything

```sh
make deploy          # = ansible-galaxy install + ansible-playbook site.yml
```

The playbook prints the URL of each service when it finishes.

**Without Terraform:** `cp ansible/inventory/hosts.yml.example ansible/inventory/hosts.yml`, edit the IP, then run `make deploy`.

### 3. Update

```sh
make update                          # pull new images, recreate what changed
make update SERVICES=radarr,sonarr   # only these
make update-os                       # apt dist-upgrade (incl. Docker) + containers
```

Images follow the `latest` tag by default. To pin a version, see below.

### What gets configured automatically

| App | Setup |
|---|---|
| **qBittorrent** | No login from local networks (`qbittorrent_auth_bypass_subnets`). Saves to the downloads folder; each app gets its own category subfolder. |
| **Radarr / Sonarr** | No login page. Fixed API keys. Root folder set to movies or series. qBittorrent added as the download client. |
| **Configarr** | Syncs the TRaSH quality profiles and custom formats into Radarr and Sonarr (*HD Bluray + WEB*, *WEB-1080p*). Change the templates in `integrations.yml`. |
| **Prowlarr** | No login page. Radarr and Sonarr connected with full sync, so indexers show up in them automatically. FlareSolverr added as a proxy. Adds the indexers listed in `prowlarr_indexers`. |
| **Bazarr** | No login. Connected to Sonarr and Radarr. Language profile from `bazarr_languages` applied by default. Uses free subtitle providers (`bazarr_providers`). |
| **Seerr** | Radarr and Sonarr pre-added, with the default profiles and folders. |

**Indexers** are whatever you list. Public ones (`1337x`, `yts`, …) need just a name; private ones also need credentials:

```yaml
prowlarr_indexers:
  - name: 1337x
    flaresolverr: true       # behind Cloudflare
  - name: yts
```

If an indexer can't be reached, the deploy prints a warning and carries on.

**API keys** are generated on the first run and stored in `ansible/secrets/<host>/`. That folder is git-ignored, so back it up. If you lose it, the next deploy creates new keys and re-wires everything; add `-e configure_force=true` to push them to every app.

## Services on other machines

Anything else you run (Jellyfin on another LXC, the Proxmox UI, your router…) can be added in `ansible/group_vars/all/proxy.yml`. Each entry gets a homepage tile; give it a `path` or `subdomain` and Traefik serves it on your domain too:

```yaml
external_services:
  jellyfin:
    url: http://192.168.1.20:8096        # where it really runs
    subdomain: jellyfin                  # -> http://jellyfin.fakeflix.meme.ar
    homepage:
      name: Jellyfin
      group: Watch
      description: Movies & shows
      widget: { type: jellyfin, key: "<Jellyfin: Dashboard -> API Keys>", enableBlocks: true }
  proxmox:
    url: https://192.168.1.10:8006
    subdomain: proxmox
    insecure: true                       # self-signed certificate
    homepage: { name: Proxmox, group: Infra }
  router:
    url: http://192.168.1.1              # no path/subdomain = homepage link only
    homepage: { name: Router, group: Infra }
```

Then run `make deploy`. Only the config is touched; nothing is restarted except Traefik and Homepage.

**Folder or subdomain?** A subdomain always works. A folder (`path: /jellyfin`) only works if the app knows it lives there:
- If the app has a "base URL" setting (Jellyfin: Dashboard → Networking → Base URL), set it to the same path.
- If it has none, try `strip_prefix: true`. That works for simple apps but breaks apps that use absolute links; use a subdomain for those.

Widget types and their fields (API keys etc.) are listed at [gethomepage.dev/widgets](https://gethomepage.dev/widgets/). The widget's `url` defaults to the service's `url`.

## Logins

Everything that can run without a password does.

| App | URL | Login |
|---|---|---|
| Homepage | `http://fakeflix.meme.ar/` | none |
| Radarr | `http://fakeflix.meme.ar/radarr` | none |
| Sonarr | `http://fakeflix.meme.ar/sonarr` | none |
| Prowlarr | `http://fakeflix.meme.ar/prowlarr` | none |
| Bazarr | `http://fakeflix.meme.ar/bazarr` | none |
| qBittorrent | `http://fakeflix.meme.ar/qbittorrent` | none from `10.x`, `172.16-31.x` or `192.168.x` addresses (see below) |
| Seerr | `http://requests.fakeflix.meme.ar` | **your Jellyfin account**, one-time setup below |
| FlareSolverr | `http://<ip>:8191` | none (API only, no UI) |

Replace `fakeflix.meme.ar` with your `proxy_domain`, and use `https` if you enabled it. Without the domain, each app is still at `http://<ip>:<port>` plus its folder, e.g. `http://<ip>:7878/radarr`.

### Seerr: first-time setup with Jellyfin

Seerr has no "no login" mode: its users *are* your Jellyfin users. The first time you open it:

1. Go to `http://requests.fakeflix.meme.ar` (or `http://<ip>:5055`) and pick **Jellyfin**.
2. Enter your Jellyfin server's LAN address, e.g. host `192.168.1.20`, port `8096`. Depending on the version this is one URL field or separate host and port fields. Don't use `localhost`: Seerr runs in its own container. Sign in with your **Jellyfin admin** username and password. The email field is only used for notifications. That account becomes the Seerr admin.
3. **Sync libraries**, tick your Movies and Shows libraries, then continue.
4. **Services:** Radarr and Sonarr are already there. Click **Finish**.

To let other people request things, go to Settings → Users → **Import Jellyfin Users**. They then log in with their own Jellyfin accounts.

### qBittorrent outside your LAN

Clients from the subnets in `qbittorrent_auth_bypass_subnets` (all private ranges by default) skip the login. qBittorrent trusts Traefik's forwarded address, so the check also applies to the real client through the proxy. Anywhere else (the internet, or a VPN using another range), qBittorrent asks for `admin` plus a password. The linuxserver image generates a temporary password on every start until you set one. Find it with `docker logs qbittorrent`, then set a permanent one under Tools → Options → Web UI.

### Turning logins back on

- Radarr, Sonarr, Prowlarr: set `arr_auth_method: Forms` in `ansible/group_vars/all/integrations.yml` and re-deploy. Each app then asks you to create a user on first visit.
- qBittorrent: set `qbittorrent_auth_bypass_subnets: []`.
- Bazarr: Settings → General → Security.
- Or protect everything at once with `proxy_basic_auth_users` (see above).

## Adding or changing services

Don't edit the default catalog. Use the two dicts at the bottom of `ansible/group_vars/all/services.yml`, or put them in `ansible/host_vars/<host>.yml`, where they take precedence:

```yaml
stack_extra_services:
  jellyfin:
    image: lscr.io/linuxserver/jellyfin
    linuxserver: true      # adds PUID/PGID/TZ/UMASK
    media: true            # gets all media_mounts
    ports: ["8096:8096"]
    web:                   # served at /jellyfin (also set Base URL /jellyfin in its Networking settings)
      path: /jellyfin
      homepage: { group: Watch, description: Movies & shows, widget: jellyfin }
    extra:                 # any raw compose keys
      devices: ["/dev/dri:/dev/dri"]

stack_service_overrides:
  radarr:
    tag: "5.14.0"          # pin a version
  bazarr:
    enabled: false         # disabled services are removed on next deploy
```

Then run `make deploy`. The schema is documented at the top of `services.yml`.

To wire a new service into the others automatically, add `ansible/roles/configure/tasks/<service>.yml` and include it from `roles/configure/tasks/main.yml`. `arr_resource.yml` creates or updates any Servarr download client, application, indexer or connection in one call. See `prowlarr.yml` for examples.

If a service needs more than a compose entry (config files, host packages and so on), add a role under `ansible/roles/` and list it in `site.yml`.
